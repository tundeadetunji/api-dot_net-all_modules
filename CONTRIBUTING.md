# Contributing to Code Repertoire

Thank you for your interest in contributing to Code Repertoire! Whether you'd like to fix a bug, improve an existing module, add a feature, strengthen the tests, or suggest an improvement, your input is welcome. The goal is to build a useful, reliable library that others can confidently use and contribute to.

## Getting started

1. Read the README to familiarise yourself with the project's modules and supported framework.
2. Check the existing issues to see what needs attention and whether someone is already working on it.
3. If you find an issue you'd like to work on, leave a comment to let others know. For substantial changes, new features, or work that affects shared APIs, discuss your proposed approach in the relevant issue before investing significant time.
4. If you discover a bug or have an improvement in mind that isn't covered by an existing issue, feel free to open a new one. For substantial proposals, allow some time for discussion so that we can agree on the scope and direction before implementation.
5. Fork the repository and create a branch for your changes.

You don't need to wait for maintainer assignment to tackle an existing, actionable issue, provided it isn't blocked or dependent on other work. If you're unsure whether a change needs prior discussion, just ask in the relevant issue.

## Development

- Follow the existing coding conventions unless a different approach has been agreed upon.
- Keep changes focused on one issue where practical.
- Add or update tests for changed behaviour.
- Discuss breaking changes before implementing them.
- For work that depends on another change, or that overlaps with work already in progress, coordinate with the people involved before proceeding.
- Never commit passwords, API keys, connection strings containing secrets, or other credentials.

## Submitting changes

1. Build the solution and run the relevant tests.
2. Submit a pull request against the `master` branch.
3. Explain what changed, why it was needed, and how it was tested. Link the relevant issue where applicable.
4. Be prepared to discuss your approach and address review feedback.

Every contribution is an opportunity to improve the project. All pull requests are subject to maintainer review, and changes may need revision before they can be merged. Submitting a pull request does not guarantee acceptance, but thoughtful proposals and constructive discussion are always welcome.

Thank you for helping make Code Repertoire better!

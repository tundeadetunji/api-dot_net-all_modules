# Security Policy

## Reporting a Vulnerability

Thank you for helping keep Code Repertoire and its users safe.

If you discover a potential security vulnerability in this project, please report it responsibly so that it can be investigated and addressed.

**Please do not disclose suspected security vulnerabilities in public GitHub issues or pull requests until they have been investigated and, where appropriate, resolved.**

### How to Report

The preferred method is to use GitHub's private vulnerability reporting feature.

Alternatively, please contact the project maintainer privately through GitHub to arrange a secure way to share the details.

When reporting a vulnerability, please include as much of the following information as possible:

- A description of the vulnerability and the affected module or component.
- The potential impact and circumstances under which it can be exploited.
- Steps to reproduce the issue, including a proof of concept where appropriate.
- Any suggested mitigation or fix, if you have one.

Please avoid including real credentials, personal information, or sensitive production data in your report.

### What Happens Next?

Reports will be reviewed to assess their validity, severity, and potential impact.

Where appropriate, the maintainer will work on a fix, assess whether other parts of the project are affected, and coordinate disclosure once the vulnerability has been addressed.

Please understand that response and resolution times may vary depending on the complexity and severity of the issue.

### Scope

This policy applies to security vulnerabilities affecting Code Repertoire and its maintained components.

If you are unsure whether an issue constitutes a security vulnerability, please report it privately rather than disclosing potentially sensitive details publicly.

Thank you for helping improve the security and reliability of this project.
